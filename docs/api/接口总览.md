## 1. 先看这页能解决什么

本页用于统一查阅五件事：**接口地址是什么、做什么、代码在哪里、需要谁的结果、下一步调用谁**。

- 后端根地址：http://127.0.0.1:8080 。
- 表格中的 URL 是后端相对路径；例如 /api/v1/imports 的完整地址是 http://127.0.0.1:8080/api/v1/imports 。
- 前端开发地址：http://127.0.0.1:5173 。前端通过代理访问同一套接口，不是另一套后端。
- “已实现”指有真实代码；最近功能验收见 第30～31轮集中交付（本机历史记录），历史功能见 第 04 轮（本机历史记录）。
- “仅规划”指设计中存在，但现在不能调用。没有实现的类标为“待设计”。

### 接口与类怎么区分

Controller 类接收 HTTP 请求，Service/Store/Mapper 执行业务或查询。下面出现的“上下游调用”主要是数据依赖，**不是后端控制器通过 HTTP 互相调用**。

### N1～N4：字段、关系与异常

N1 请求头 `Idempotency-Key` 与项目创建相同，只允许1～128位ASCII字母、数字、点、下划线、冒号或横线。JSON体为 `instruction`（必填，去首尾空白后1～1000字）与 `snapshotId`（可选）。项目只有一份资料时可自动绑定；零份返回409并要求先添加，多份而未指定返回409并要求选择。指定快照不属于项目返回404。同项目同键同资料同原话首次201、重发200；同键更换资料或原话返回409。

当前确定性路由支持“总结讨论、整理观点、梳理逻辑/理由、比较谁更有道理”等表达；不能可靠路由的要求返回422，不用最相似模板硬猜。前端只让用户写要求和选择资料，不提交 `intent`、模型、提示版本或工具。服务端保存原话、`DISCUSSION_V1` 配方、是否包含评议、绑定快照及任务身份。

N2 默认page=1、size=10，允许page 1～10000、size 1～50。N3 返回 `id/projectId/snapshotId/instruction/status/jobId/artifactId/lastErrorCode/createdAt`；状态为PENDING/RUNNING/SUCCESS/FAILED。`artifactId` 只在任务和请求同事务发布成功后出现。

N4 在未成功时返回409。关闭模型时继续返回 `discussion-artifact-v1` 与 `STRUCTURAL_DEMO`：只组织根评论、回复原文和确定的 `REPLY_TO`，语义保持UNKNOWN。显式开启并完成模型调用时返回 `discussion-artifact-v2` 与 `MODEL`：包含 issues、claims、relations、assessments、evidence 和 limitations；每个模型结论都必须引用当前输入的commentId，发布时原文从绑定快照读取。`MORE_SUPPORTED` 只表示当前材料内论据更充分，不证明外部事实为真。两种模式都以 `scope.truncated` 明示范围。

关系：P1/P5确定项目与资料 → N1保存目标并创建同一个analysis_job任务 → N3轮询 → N4读不可变产物。旧反馈入口T1～R6继续只处理FEEDBACK任务；H1和资料卡片的旧报告入口过滤FEEDBACK，避免把讨论产物误当情感报告。

## 3. 常用参数、返回值与错误

### P1～P6：项目创建与资料挂载

P1 为 application/json，请求头 Idempotency-Key（1～128位ASCII字母、数字、点、下划线、冒号或横线），请求体 name／analysisGoal，不能为空或全空白；长度上限分别120／1000个Java UTF-16单元。去首尾空白后同键同内容201首次／200复用；同键不同内容409，非法400。Location指向P3。

项目字段：id、name、analysisGoal、createdAt、workCount、snapshotCount、jobCount。作品数按已挂载快照的不同contentId，版本数按关系条数；任务数是这些快照上所有任务，包括挂载前任务。同快照挂入多个项目时历史共享，不是每项目私有执行记录。

P2默认page=1、size=12；P5默认page=1、size=20。页码1～10000、size1～50，返回items／total／page／size／totalPages；越界页items空，空集合totalPages=0。项目按createdAt及ID倒序；资料按首次挂载流水倒序，不随重复挂载改变。

P4为JSON体 { "snapshotId": "已存在快照UUID" }，成功200并返回资料摘要；重复不新增关系、不更改旧正文与加入时间。项目／快照不存在404，非法参数400。P3／P5／P6无项目或非当前服务器范围404，P6未挂载404。

资料摘要包含snapshotId、contentId、sourceType、sourceContentId、title、commentCount、snapshotCreatedAt、addedAt、latestJobId、latestJobStatus、reportId；最近任务严格属于这一snapshotId，尚无则相关字段null。时间是数据库本地时间。

范围由服务器 echoinsight.projects.workspace 注入，默认local、测试project-it，HTTP不接收workspace参数。本机分类不是完整身份授权；原全局任务／快照接口仍保持单用户兼容。不自动挂载同作品新版本、不自动分析，无编辑／删除接口。

I1／I4可选multipart字段projectId：提供时 ProjectImportService.ingest 在同一事务检查项目、原导入、挂载；失败整体回滚，返回原回执格式。不提供时保留原独立导入行为。当前已有快照可用P4关联，工作台新上传自动归档。

协作：P1→P3→I1/I4(projectId)→P5→T1/T2→R1/R6；回看用H1(projectId)。所有任务仍绑定单快照，项目目标本轮仅保存展示，没有更改旧分类提示。详细说明见 项目工作台（本机历史记录）。

### R6：逐条评论明细（只读）

例：GET /api/v1/reports/{reportId}/comments?page=1&size=20&label=UNKNOWN&q=边界 。

| 参数 | 默认 | 允许范围与含义 |
| --- | --- | --- |
| page | 1 | 1～10000，超过末页返回空 items，total 不改变 |
| size | 20 | 1～100，工作台固定 20 |
| label | ALL | ALL / POSITIVE / NEGATIVE / NEUTRAL / UNKNOWN，严格大写 |
| q | 空字符串 | 最多 100 个 Unicode 码点，长度检查后去首尾空白，忽略大小写的当前正文子串 |

200 返回 reportId、snapshotId、jobId、sourceMode、snapshotCommentCount、labelCounts、label、query、total、page、size、totalPages、items。labelCounts 含 positive / negative / neutral / unknown，为全快照数量；total 为条件匹配数；无匹配 totalPages=0。sourceMode 来自原报告。

items 含 commentId、sourceCommentId、text、occurredAt、label、parent、findingIds。parent 为同快照直接父评论的 commentId / sourceCommentId / text，或 null；findingIds 是 R3 使用的稳定身份，没有引用为 []。时间来自旧快照的输入时间点，序列化可统一为 UTC，并非查询时间。按已保存的规范化快照顺序（导入按 sourceCommentId 排序），不按上传行序或分类响应顺序。

q 不匹配来源 ID、父评论、标题、字幕，不解释 SQL 通配符或正则。当前最多 5000 条 JSON 材料在内存筛选分页，不是数据库行级分页。400 参数/类型非法，404 无报告或误传 jobId，500 保存的快照/分类缺失或与报告不一致；不自动补标签、重分析或修复历史。响应 no-store / nosniff，无数据库写入。

协作：T2/H1 得 reportId → R1 看摘要 → R6 查全部原始标签，findingIds 可关联 R3；R4 仍只追加结论核验，不改 R6 标签；R5 仍只导出原报告及引用。详细字段与操作见 明细说明（本机历史记录）。


### S3：当前新任务模式（只读）

成功 200，返回 mode、providerId、modelVersion、unit、taskBudgetUnits、taskBudgetUsd。默认 mode=MOCK、unit=SIMULATED_UNITS、预算为 0；启用配置完整时 mode=MODEL、unit=USD_NANOS，taskBudgetUsd 是精确十进制字符串。“模型与说明”页面读取此接口展示安全运行摘要。响应没有密钥、供应商地址、余额或完整配置；读取不创建任务、不发送模型请求，也不等于供应商健康检查。

页面在创建前读取；失败时禁用创建并允许重新读取。价格和开关仅在本机配置，不能 POST 这个接口改变收费状态。历史任务来源看 T4 固定计划和 R1 provenance；本接口只代表现在创建的新任务。

### I1：上传 JSON

- Content-Type：multipart/form-data，文件字段名必须是 file。
- 文件要求：.json、UTF-8、最大 2 MiB；schemaVersion=1.0。可选projectId，项目校验与归档和导入同一事务；非法／无项目不留下孤立回执。
- 评论 1～5000 条，字幕 0～1000 段；更详细输入契约见 导入文档（本机历史记录）。
- 成功：201，返回导入 id、contentId、snapshotId、status、读取/有效/重复/新增修订数量。新增 rawRecordCount=importedComments（去重前行数）、snapshotCommentCount=eligibleComments（快照评论数），旧字段保持原义。
- 每个成功请求保留一份回执；相同内容可复用快照和修订，但回执 ID 可以不同。
- 常见错误：400 缺少文件或上传结构错误；413 超限；422 数据、编码或 JSON 校验失败。

### I4：MediaCrawler 平台导出导入

Content-Type multipart/form-data。platform=BILIBILI / XHS（严格大写），sourceContentId 为导出里的 video_id / note_id，不能填 URL；contentsFile、commentsFile 为 UTF-8 .json 数组文件，各 1～5000 行、各最多 2 MiB，整个 multipart 最多 5 MiB。

成功 201，Location 指向原 I2。返回 receipt（原 ImportReceipt，含 id/contentId/snapshotId 和标准计数）、adapterVersion、platform、sourceContentId、contentRows、commentRows、selectedCommentRows、excludedContentRows、excludedCommentRows、contentFileSha256、commentsFileSha256、sourceTotalComments=null、warnings。selectedCommentRows 去重前；快照数读 receipt.snapshotCommentCount，排除数不计入旧回执 importedComments。

作品文件必须恰好一条选定作品元数据。其他作品行明确计数排除；缺失父评论、循环、冲突或字段不合法拒绝，不自动补造。B站时间单位秒，小红书毫秒，统一保存 UTC。额外昵称/token/点赞等不进入快照。JSONL/CSV不支持。诊断和原文件指纹仅本次响应提供，I2仍只读标准回执；尚非持久采集批次。

400 缺参数/部件；422 文件格式、平台、来源身份、时间/父关系等不合法；413 超限；415 非 multipart。校验失败不留下半份快照。不下载 URL、不接收 Cookie、不创建任务或发模型请求。新 sourceType 明确为 BILIBILI/XHS，免费 Mock 不对它们查合成标签。

平台映射与真实联调见 说明（本机历史记录）。I4 → receipt.snapshotId → T1；后续 R1/R6/R5 查询、明细和导出继续复用。弹幕本轮只在真实联调材料中独立暂存，不通过 I4 导入或计入评论分母。

### T1：创建任务

请求头：

```text
Content-Type: application/json
Idempotency-Key: 为本次逻辑请求生成的唯一字符串
```

请求体：

```json
{ "snapshotId": "I1 返回的快照 UUID" }
```

- 成功：202。返回值中的 id 是任务 ID，Location 也指向该任务查询 URL。
- 同一请求键 + 同一快照：返回原任务，不重复创建；即使服务器配置改变，仍保留原任务固定计划，不覆盖报价或模型。
- 同一请求键 + 不同快照：409。快照不存在：404。
- 请求键为 1～128 位 ASCII 字母、数字、点、下划线、冒号或横线。缺失或非法输入返回 400。
- 返回 202 只表示任务已保存；是否执行完必须看 T2 的 status。新任务使用服务器当前校验过的计划，客户端不能指定供应商、端点、价格或额度；默认仍免费 Mock。

### H1：任务历史列表

例：http://127.0.0.1:8080/api/v1/analysis-jobs?page=1&size=10&status=SUCCESS 。

| 参数   | 默认值 | 允许范围                                   | 用途            |
| ------ | ------ | ------------------------------------------ | --------------- |
| page   | 1      | 1～10000                                   | 页码，从 1 开始 |
| size   | 10     | 1～50                                      | 限制一次读取量  |
| status | 不筛选 | ALL / PENDING / RUNNING / SUCCESS / FAILED | 限定列表状态    |
| projectId | 不筛选 | P1/P2/P3的项目ID | 仅列明确挂载快照上的任务；无效或非范围项目404 |

返回 items、total、page、size、totalPages。每条包含任务 id、snapshotId、标题、sourceType、status、attempts、createdAt、reportId。创建时间为数据库本地时间，未伪装成 UTC。

排序为创建时间倒序，再按任务 ID 倒序；相同时间下仍有稳定顺序。越界页返回空 items 并保留真实 total；非法参数返回 400。没有匹配记录时 totalPages=0。

这是只读接口。它不会开始分析、重试失败任务，也不会生成新报告。

### T2 / T3：进度和重试

- T2 成功返回 200。主要字段：id、snapshotId、status、progress、attempts、lastErrorCode、reportId、steps、history。
- progress 是保存步骤对应的阶段进度，不是逐条评论百分比，也不估计剩余时间。
- status：PENDING 等待处理、RUNNING 处理中、SUCCESS 已完成、FAILED 失败。
- history 记录每次执行，保留失败或租约失效信息。
- T3 不需要请求体，成功返回 202；非 FAILED 或存在 SENT / OUTCOME_UNKNOWN 模型调用时返回 409。未知状态尚无对账入口，不能盲目再发请求。
- 重试复用原任务和已成功步骤，不是另建一个任务。
- lastErrorCode 保留上次错误；判断当前是否失败应看 status。

### T4：分批与调用明细

page 默认 1、范围 1～10000；size 默认 20、范围 1～100。成功 200；参数非法 400、任务不存在 404。任务 ID 来自 T1、H1 或 T2。只读查询不初始化账本、不调用模型，也不会更新历史任务。

| 返回字段                                        | 含义及使用关系                                                                                                                                                                                                                                                               |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| jobId                                           | 与 T2 的任务 id 一致                                                                                                                                                                                                                                                         |
| plan                                            | 固定的 providerId、modelVersion、promptVersion、taxonomyVersion、batchSize、timeoutMs、maxOutputTokens、unit、priceVersion、inputUnitRate、outputUnitRate、budgetLimit；新计划可含 inputTokenCeiling、responseModel、executionMode；按 unit 区分模拟与美元估算，详见字段说明 |
| budget                                          | limitUnits 上限、reservedUnits 未结清预留、settledUnits 已结算、unit 单位                                                                                                                                                                                                    |
| total / page / size                             | 已建立批次记录总数与当前分页；不是预估最终批次数                                                                                                                                                                                                                             |
| items[].index / status / attempts               | 从 0 开始的批次编号、状态、物理调用尝试数；页面编号从 1 展示                                                                                                                                                                                                                 |
| items[].recentCalls                             | 每批最近最多 3 次尝试；不是完整历史分页                                                                                                                                                                                                                                      |
| recentCalls[].id / state                        | 调用身份；RESERVED / SENT / SUCCEEDED / RELEASED / OUTCOME_UNKNOWN                                                                                                                                                                                                           |
| recentCalls[].reservedUnits / settledUnits      | 此次尝试预留与结算；未知结算可为 null                                                                                                                                                                                                                                        |
| recentCalls[].inputTokens / outputTokens        | Mock 为 0；未知为 null，不能伪造为 0                                                                                                                                                                                                                                         |
| recentCalls[].requestId / errorCode / createdAt | 供应商请求标识（可空）、脱敏错误码、UTC Z 创建时间                                                                                                                                                                                                                           |

unit=SIMULATED_UNITS 为模拟，默认 Mock 单价和用量均为 0；USD_NANOS 是十亿分之一美元的本地估算，非供应商账单，不精确拆缓存/峰谷优惠。inputTokenCeiling 是预留政策上界，不是实际用量；responseModel 是独立核对的响应身份；executionMode 是来源。公开 T1 不能自行指定付费计划。旧任务使用历史免费 Mock 计划，可能没有批次记录，返回 total=0。响应不包含原始评论、请求正文、密钥或供应商地址。

任务可能记录 MODEL_BUDGET_EXCEEDED、MODEL_CAPACITY、MODEL_OUTCOME_UNKNOWN、MODEL_PLAN_CHANGED 等安全错误码；底层超时或无效响应的原因可见 recentCalls[].errorCode。批次 READY / RUNNING / SUCCEEDED / OUTCOME_UNKNOWN 与任务状态不是同一层。具体业务原因和恢复边界见 业务说明（本机历史记录）。

### R1 / R2：报告与证据

- 两者成功均返回 200，不存在返回 404。
- R1 包含 reportId、snapshotId、version、provenance、coverage、metrics、findings、limitations。旧 Mock 为 version=1；新来源为 version=2，provenance.mode 区分 MOCK / LOCAL_STUB / MODEL，后两者含 providerId、verifiedResponseModel、priceVersion、billingUnit。模型响应身份匹配不证明权重固定或标签正确。
- R2 返回 commentId、sourceCommentId、text。commentId 对应 R1 的 findings[].evidenceIds。
- 正面占比的分母是 classifiedComments；UNKNOWN 不进入该分母；分母为零时比例为 null。
- 旧报告绑定旧快照，不会因为后续重新导入而变成新原文。
- 新生成报告增加 coverage.snapshotCommentCount，等于 eligibleComments。历史报告可以缺此字段，不回填；报告 importedComments 仍为快照数，与回执同名字段不是同一口径。

### R5：下载报告

- 查询参数 format：默认 markdown，仅 markdown / json；includeReviews：默认 true，布尔值，控制是否附每条结论最新核验。
- 成功 200，响应为 UTF-8 附件：text/markdown;charset=UTF-8 或 application/json。Content-Disposition 固定为 echoinsight-report.md / echoinsight-report.json，同时 no-store、nosniff；不接受任意文件路径或名称。
- 400：格式不支持或布尔参数非法。404：报告不存在，包括误传 jobId。数据完整性损坏时拒绝导出，不跨快照补原文。
- JSON：exportVersion=1.0、exportedAt、report（原 JSON，不回填核验）、evidence、reviewsIncluded、reviewSummary。
- evidence：commentId、sourceCommentId、text，只含原引用。reviewSummary：findingIndex（对应 report.findings 的从 0 开始位置，不替代核验 ID）、findingId、reviewCount、latestReview（可空）、latestCorrectedEvidence；最新事件保持 R3/R4 的身份、修订、verdict、reason 和 UTC 时间原义。
- 不包含核验时 reviewSummary=[]；没有意见时 latestReview=null。只导出最新意见及总修订数，不声称导出全部核验历史。附录替代原文仍来自相同快照，不替换 report.findings 或原 evidence。
- 不写业务记录、不建立分析任务、不调用模型。原报告稳定；导出时间或最新核验可能变化，附件不承诺重复下载字节完全相同。详细字段与原因见 报告导出说明（本机历史记录）。

### R3 / R4：人工核验

R3 可带 limit，默认 20、范围 1～100，表示每条结论最近的历史数量。返回 reportId、snapshotId、reviewerId=local、historyLimit、findings。每条包含稳定 findingId、claim、evidenceIds、原文 evidence、最新替代原文 latestCorrectedEvidence、全部修订数 reviewCount 和倒序 history。没有意见时 history 为空，reviewCount=0；读取没有写入副作用。

findingId 为服务器生成的 f_ 加 64 位十六进制 SHA-256，不能用数组下标、commentId 或其他报告的 ID 代替。原报告 JSON 不增加或回填此字段，R3 是核验身份的唯一获取入口。

R4 请求头使用 Content-Type: application/json 和 Idempotency-Key（1～128 位 ASCII 字母、数字、点、下划线、冒号、横线）。请求示例：

```json
{
  "verdict": "PARTIAL",
  "reason": "原文支持样本判断，不能推出总体观众态度。",
  "correctedEvidenceIds": [],
  "expectedRevision": 0
}
```

- verdict 必填，可为 SUPPORTED / PARTIAL / UNSUPPORTED / UNCERTAIN。
- reason 必填，非空且最多 1000 个字符；保存时去除首尾空白。
- correctedEvidenceIds 必填数组，可为空，最多 10 个唯一 ID，每个最多 128 字符，必须属于该报告快照；空数组表示不提出替代证据，不表示删除原引用。
- expectedRevision 必填，取 R3 的 reviewCount，初次为 0，允许 0～1000000000。
- 首次保存 201；同键同规范化载荷重放 200。返回 {review,replayed}，review 包含事件 id、reportId、findingId、revision、verdict、reason、correctedEvidenceIds、reviewerId=local、createdAt（UTC，Z）。
- 400：缺头、表单或参数错误。404：报告或结论不存在。409：同键异载荷、不同报告复用键或修订过期。422：引用重复或越过快照范围。错误采用 Spring 标准格式，不承诺统一 issues 数组。
- 旧成功请求在后续修订出现后仍可按原键重放，返回原事件，不重新检查为新提交；新修改需要新的请求键和当前修订。
- 应用仅追加意见，不修改旧记录、原报告或快照。当前固定 local 身份，没有认证、多用户或租户隔离；超过 100 个修订的更早记录仍保留，但暂无页面分页入口。

> 校验错误响应并非全项目统一格式：导入校验返回 INVALID_IMPORT 和 issues；任务、历史参数等目前使用 Spring 标准错误响应。前端不能假设所有错误都有 issues 字段。

## 4. 接口之间的关系

### 路径 A：从新文件生成报告

```text
I1 上传文件
 ├─ 导入 id ──────→ I2 查询导入回执（可选）
 └─ snapshotId ───→ I3 查看快照原文（可选）
                  └→ T1 创建任务 → 任务 id
                                  └→ T2 查询任务进度
                                      ├─ FAILED → 检查 T4 → 可安全恢复时 T3 重试 → 再查询 T2
                                      └─ SUCCESS → reportId
                                                   ├→ R1 报告内容
                                                   └→ R2 原文证据
```

### 路径 B：直接打开已有报告

```text
H1 读取历史
 └→ 选择任务 id → T2 查询详情
                  └→ 已完成且有 reportId → R1 + R2
```

这条路径不需要重新上传文件，也不会调用 T1。

### 路径 C：核验旧报告

R1 得到 reportId → R3 读取结论 findingId、原文和 reviewCount → R4 带 expectedRevision 提交 → R3 回看新修订及旧历史。替代原文来自同一个 I3 快照；不会启动 T1、改变 R1 的模型结论或调用真实模型。

### 这些 ID 不能混用

| 名称                      | 从哪里获得              | 用在哪里                                 |
| ------------------------- | ----------------------- | ---------------------------------------- |
| 导入 id                   | I1 / I2                 | /imports/{id}                            |
| contentId                 | 导入回执                | 服务器作品标识；目前没有独立作品详情接口 |
| snapshotId                | I1、I2、H1、T2          | /snapshots/{id}，以及 T1 请求体          |

### SR1字段与核验口径

- `targetKind`：ISSUE/CLAIM/RELATION/ASSESSMENT。`targetId`：议题ID、观点ID、关系数组从0开始的字符串序号、或评议的issueId；均来自N4原产物，不能借其他请求身份。
- `verdict`：SUPPORTED/UNSUPPORTED/UNCERTAIN（有依据/依据不充分/暂无法判断）。`reviewer`：1～80字本机署名，非登录身份。`rationale`：1～2000字理由。
- `evidenceIds`：0～20个不重复的当前产物证据ID。代码检查存在与归属，**不自动证明语义支持**。
- 返回`id/requestId/artifactId/input/createdAt`；目标或证据非法400，未发布409，越项目/工作空间404。新意见用新键追加，历史不覆盖；不自动生成准确率或独立金标准。

### CR1～CR3候选发现字段

`url`为HTTPS `space.bilibili.com/{数字UID}`（可含/video及普通查询参数），拒绝用户信息、端口、编码路径或伪造主机。`keyword`可空/最多80字且无控制字符。`candidateLimit`默认10、1～20；工具固定从第一页取、page-size=30、pubdate排序，无Cookie/自动重试。当前是平台关键词，不是语义分类。

Run含`id/projectId/ownerMid/keyword/candidateLimit/status/attempts/lastErrorCode/rawSha256/result/createdAt`；result仅SUCCESS时存在，含candidates（bvid/aid/title/publishedAt/服务器重建url）、completeness、selectionMethod、limitations。达到候选上限为TRUNCATED，否则NOT_PROVEN；空结果不证明整个空间为空。原始JSON仅服务端存档，不通过接口暴露。无能力503；输入400；同键不同范围409。FAILED不自动重试，用户可新建一次检索；过期认领最多3次，耗尽DISCOVERY_LEASE_EXHAUSTED。

### CR4～CR7组合采集与冻结字段

`discoveryId`必须是同项目成功发现；`bvids`必须为该次候选内1～5个不同BV号，顺序不影响幂等；`rootLimit`默认20、1～200且每个作品独立适用。

Group含`id/discoveryId/status/rootLimit/succeeded/failed/pending/items/limitations`，每项带bvid/title及原CollectionStore.Batch（C2）。部分终态失败为PARTIAL_FAILED，全失败FAILED；子任务重试由C4显式处理。组没有自己的Worker，不接受“某组成功”的外部写入。

CR7需`name`1～120字、`collectionIds`1～5个不同成功子批次ID。尚有未结束任务409，非组内/失败成员400；只保存用户明确子集，不补入失败作品。创建清单不会触发LLM。相同正文被后续采集复用时，仍绑定所选子批次的完整性/平台声明数；旧F1冻结逻辑与历史指纹保持兼容。

### ER1/ER2对照字段

`schemaVersion=manifest-evidence-v1`；`dependencySha256`绑定规则、冻结成员/来源诊断/原文哈希、子状态及错误、产物身份及正文。`works`保留全部成功和失败成员；`topics`仅按NFKC、空白和大小写规范化后的问题精确分组，workCount按不同快照计数。

每个topic.sources切片有requestId/artifactId/snapshotId/title/sourceMode/sourceCompleteness/scope/issue/claims/assessments/evidence。证据只从本作品产物提取。报告不做跨作品语义归并、共识或总胜负判断；STRUCTURAL_DEMO不会因此变成MODEL。人工核验另走SR1/SR2，不修改原报告依赖。重试活跃期409，越项目404；GET和导出均不产生模型费用。
